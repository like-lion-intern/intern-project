# LLM 분석 및 리포트 생성 통합 작업 요약

이 문서는 기존의 분산되어 있던 AI 강의 분석 결과물(JSON 파일들)을 바탕으로, 최종 강사 피드백용 **마크다운(Markdown) 리포트를 자동 생성**하기 위해 진행된 시스템 통폐합 및 리팩토링 과정의 구체적 내용을 정리한 문서입니다.

---

## 1. 개요 및 배경

- **문제점**: 기존 코드베이스(`JH_Codes`)는 STT 스크립트를 정밀하게 분석하고 항목별 점수를 도출해내는 훌륭한 계산 엔진(로직)을 가지고 있었습니다. 그러나 최종 리포트를 생성하는 기존 `prompts.py`는 이 계산된 결과를 활용하지 않고, 원문 스크립트를 LLM에게 통째로 주어 **"처음부터 다시 분석하고 리포트를 써라"**는 식의 구조(One-Shot)로 설계되어 있었습니다. 이는 분석 엔진과 LLM의 평가가 엇갈릴 수 있는 무결성 문제를 일으킵니다.
- **해결책**: `prompts.py`를 '분석 도구'에서 **'리포트 시각화 및 문장 합성 도구'**로 역할을 변경하고, 기존 엔진이 생성한 3개의 JSON 파일(`_evidence.json`, `_analysis.json`, `_result.json`)을 조립하여 LLM에게 전달하는 전용 생성기(`report_generator.py`)를 구축했습니다.

---

## 2. 구체적인 작업 내용

### 2.1. `prompts.py` 역할 재정의 (리팩토링)

> **AS-IS**: LLM이 직접 18개 항목을 분석하고 점수를 매기도록 지시.
> **TO-BE**: `JH_Codes`가 미리 계산한 점수와 분석 코멘트(JSON)를 제공받아, 이를 예쁘게 포장하고 공감되는 피드백 문장으로 합성하도록 지시.

- **시스템 페르소나 변경**: '평가 전문가'에서 **'교육 컨설팅 리포트 디자인 및 편집 전문가'**로 변경했습니다.
- **합성 지침(SYNTHESIS_GUIDELINE) 추가**:
  - 제공된 수치(점수)와 텍스트(근거 문장)를 절대 임의로 조작하지 말 것.
  - 1~5점 점수표에 따라 적절한 시각적 스티커(🟢, 🟡, 🔴)를 제목 옆에 부착할 것.
  - 건조한 분석 이유(reason)를 바탕으로 강사에게 와닿는 부드럽고 구체적인 '개선 제안(Action Plan)' 문장을 창작할 것.
- **출력 포맷(`OUTPUT_FORMAT`) 유지 및 개선**: `example1.md`에서 요구된 수준 높은 성적표 양식, 강점/약점 요약, 단기/중장기 액션 플랜 구조를 유지하되, 데이터 삽입이 용이하도록 템플릿화했습니다.

### 2.2. `JH_Codes/report_generator.py` 신규 생성

> 흩어져 있는 JSON 결과물들을 끌어모아 LLM에 주입하는 **'데이터 연동 엔진'**입니다.

- **데이터 수집 로직**: `pipeline.py`가 생성한 특정 날짜의 `_evidence.json`, `_analysis.json`, `_result.json` 파일 3개를 동시에 로드합니다.
- **컨텍스트 압축**: LLM의 토큰 효율성을 고려하여, 3개의 파일에서 리포트 작성에 꼭 필요한 핵심 데이터(총점, 카테고리별 점수, 세부 분석 이유, 근거 발화 텍스트, 커리큘럼 일치도 등)만 추출해 하나의 통합 JSON 문맥(`combined_context`)으로 재조립합니다.
- **LLM 통신 (Gemini API)**:
  - 구글의 최신 SDK(`google-genai`)를 활용하여 통신합니다.
  - 위에서 재조립한 JSON 텍스트와 리팩토링된 `prompts.py`의 지시사항을 합쳐 Gemini(모델: `gemini-2.0-flash`) 모델에 전달합니다.
- **출력 (Markdown 저장)**: LLM이 응답한 마크다운 형태의 텍스트를 `results/{date}_report.md` 파일로 최종 물리 저장합니다.

### 2.3. 파이프라인 통합 (`pipeline.py` 업데이트)

> 데이터 전처리부터 최종 Markdown 문서 출력까지 "원클릭 자동화"를 달성했습니다.

- **기존 흐름**: Step 1(전처리) ~ Step 6(커리큘럼 매칭)까지만 수행하고 JSON을 내뱉고 종료됨.
- **변경 사항**: `main()` 함수의 가장 마지막 단계인 **Step 7**에 `generate_final_report()` 함수를 호출하는 로직을 추가했습니다.
- **효과**: 사용자가 `python pipeline.py --date 2026-02-05` 명령어 하나만 실행하면, STT 스크립트 분석부터 가중치 연산, 그리고 최종적으로 브라우저나 노션에 붙여넣기 좋은 `.md` 리포트 파일 생성까지 지체 없이 한 번에 수행됩니다.

---

## 3. 요약 및 이점 (숲의 관점에서)

1. **데이터 신뢰성 확보 (Single Source of Truth)**: LLM이 환각(Hallucination)으로 없는 점수를 지어내거나 근거 없는 평가를 내리는 것을 방지하고, 철저히 `JH_Codes` 분석 엔진의 계산된 숫자에 기반하도록 시스템 아키텍처를 교정했습니다.
2. **역할의 분리 (Separation of Concerns)**: Python 코드 엔진은 오직 '논리적 분석(숫자 연산)'에만 집중하고, LLM 프롬프트는 '사람을 감동시키는 언어적 표현과 시각적 포매팅'에만 집중할 수 있게 되었습니다.
3. **사용자 편의성**: 팀원 및 최종 소비자(강사 운영 매니저 등)는 명령 한 번으로 즉시 활용 및 복사/붙여넣기가 가능한 수준 높은 전문가 형태의 마크다운 리포트를 얻게 되었습니다.
